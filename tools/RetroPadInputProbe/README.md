# RetroPad 入力専用診断 0.1.1

0.1.1: GUIから診断を開始するとコンソール文字コード設定で落ちる問題を修正しました。
コンソールAPIではなく標準出力・標準エラーのパイプにUTF-8ライターを設定します。
子プロセス終了後のログ末尾も、両パイプの読み取り完了を待ってから終了扱いにします。

本体アプリとは独立した切り分け用ツールです。マッピングやペアリング修復は行いません。

## 使い方

1. RetroPad Mapperの全版をタスクトレイから終了します。比較条件としてSteamも終了しておきます。
2. RetroPadInputProbe.exeを起動し「Windows標準で開始」を押します。
3. 登録を削除せずにHVCを起動してA/Bを数回押します。
4. 「入力を開けました」「状態変化を受信しました」が出るか確認します。
5. 接続できた場合、観測時間内にスリープ／復帰させ、再度A/Bを押します。
6. 下の「診断ログのフォルダーを開く」から該当するJSONLを取得します。
   解凍先のlogsフォルダーにもあります。HIDパスなど個体識別情報を含むため、公開Issueにはそのまま貼らないでください。

「従来のSDL経路で開始」は比較用です。最初はWindows標準だけを試してください。
必要環境: Windows x64、.NET 8 Desktop Runtime（公開版と同じ）。
通常の入力観測は初期化後120秒。15秒間進捗がない場合、または開始から140秒を超えた場合は診断用子プロセスだけを停止します。
停止ボタン／画面を閉じる操作でも診断用子プロセスだけを終了します。既存アプリを強制終了しません。

## 比較しているもの

- Windows標準: このプロセス内だけSDLのHIDAPIを無効化し、DirectInputによる物理入力の読み取りを有効化します。
- 従来のSDL経路: Nintendo用HIDAPIを有効化します。依存SDLは本体と同じ3.1.7-c030e6fです。
- WGI、RawInput、XInput、GameInputは両条件で無効化します。
- 「出力を仮想DirectInputにする」機能とは別です。キー送信、仮想出力、設定ファイル読み書きはありません。
- 生のジョイスティックAPIを利用し、SDLゲームパッドマッピングの有無と機器を開けるかを区別します。
- 任天堂VID 057E / PID 2006または2007の候補が1台の場合だけ開きます。同じIDの実Joy-Conも候補になり得るため、
  HVC以外のJoy-Conは切断してください。候補が0台・複数台なら勝手に他の機器を開きません。
- 失敗した同じSDL instanceはその観測中に再度開きません。新しいinstanceで再登場した場合は試行します。
- ボタンと最初のハットの変化だけを記録します。アナログ軸・キー送信・ゲームでの受信は検証しません。
  入力変化という結果は、実際に押したA/Bと対応したことをユーザーが確認する必要があります。
- HIDAPI条件はSDLの通常初期化通信を行います。Windows条件はその経路を避けますが、どちらもBluetoothの
  無線状態やWindowsドライバーを完全に観測するものではありません。

## 判定の限界

Windows標準で復帰後のA/Bを読めれば、ペアリング情報が常に壊れる説は弱まり、Nintendo専用初期化経路を重点調査できます。
Windows標準でも機器が出なければ、Windows HIDデバイスの生成／無線接続側を追加調査します。
単に初期化エラーが出なくなっただけ、または候補が0台だっただけでは成功としません。
8ms待機を使う観測ツールであり、低遅延マッピングや端末からゲームまでの遅延を測るものではありません。

## 自動検証

- --self-test: コンソールなしの子プロセスで日本語の標準出力・標準エラーを完全一致検証、
  Xboxを候補にしないこと、SDLの読み込み、故意に応答を止めた子プロセスの時間制限終了。
- --run windows 3: UIなしで短時間観測。結果0=入力変化あり、10=開けた候補なし、11=開けたが変化なし、124=監視による停止。
- --ui-snapshot absolute.png: ハードウェアを初期化せず診断画面を描画。

検証ではdotnet経由だけでなく、配布するWinExeをCreateNoWindow・出力リダイレクト付きで直接起動してください。
旧版のdotnet経由テストではGUI起動時のコンソール不在を再現できていませんでした。
再現用: PowerShell 7で ./tools/RetroPadInputProbe/Test-PublishedProbe.ps1 -Executable ./outputs/input-probe-0.1.1/RetroPadInputProbe.exe

2026-09-09検証: 旧版の配布EXEをコンソールなしで起動し同じIOExceptionを再現。
修正版EXEの自己テスト2回、日本語stdout/stderrの完全一致テストに成功。
Windows標準経路の3秒観測では候補を約57msで開けましたが、入力変化は未確認（終了11）。
この短時間観測ではスリープ／復帰操作を行っておらず、再接続成功の証拠ではありません。
HVCを使ったWindows標準経路の再接続成功は未検証です。
